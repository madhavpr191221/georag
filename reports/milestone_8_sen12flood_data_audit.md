# M8: SEN12-FLOOD Local Data Audit

## Status

Initial filesystem and STAC metadata inspection is complete for the manually downloaded Kaggle copy at <code>data/sen12flood/</code>. No files were downloaded by GeoRAG. The corpus is ignored by Git. This is a structural audit, not exhaustive pixel-value validation; one representative scene was used for raster-header and visual-composite inspection.

Dataset source: [Kaggle SEN12-FLOOD](https://www.kaggle.com/datasets/virajkadam/sen12flood). The Kaggle listing identifies this as a Radiant MLHub copy and cites the original SEN12-FLOOD dataset. Kaggle currently reports the license as <code>Unknown</code>; do not redistribute the corpus or assert a Kaggle license without verification. Upstream documentation: [SEN12-FLOOD dataset documentation](https://radiantearth.blob.core.windows.net/mlhub/sen12floods/documentation.pdf).

Source and label item IDs use different collection prefixes. Sentinel-2 dates span 2018-12-13 through 2019-05-20; Sentinel-1 dates span 2018-12-15 through 2019-05-17. Sensor observations are not assumed to be same-date pairs.

The nested data tree contains 49,025 files: 32,318 TIFFs, 11,138 JSON documents, 5,567 GeoJSON files, and two PDFs. The TIFF payload totals about 14.88 GB.

A visual spot check used Sentinel-2 scene sen12floods_s2_source_0137_2019_03_10, whose paired label says flood=True and full-coverage=True. The display preview used B04/B03/B02 as true color and B08/B04/B03 as false color, with independent 2nd–98th percentile stretches for display only. This verifies that a scene can be rendered; it does not verify that its flood label is visually evident or correct.

## Important findings

- **98 Sentinel-2 items are metadata-only locally.** Their STAC items list all 12 optical bands, but all 12 referenced TIFF files are absent. The remaining 2,138 Sentinel-2 items have all 12 band files present. Keep metadata-only rows in the audit catalog with an explicit missing-assets status; exclude them from optical model inputs.
- **Coverage flags do not identify all missing rasters.** Among the 98 missing items, 88 have <code>FULL-DATA-COVERAGE=True</code> and 10 have it set to <code>False</code>. Therefore, check actual linked-file existence rather than treating this flag as a file-integrity check.
- **Flood labels are scene/date-level metadata.** <code>FLOODING</code> is stored in STAC label properties as the strings <code>"True"</code> and <code>"False"</code>; Sentinel-2 also has <code>FULL-DATA-COVERAGE</code> as a string-valued property. A sampled <code>labels.geojson</code> has zero features, so the local copy does not provide a pixel-level flood mask in that file.
- **Sequence tokens must remain strings.** There are 335 distinct textual tokens extracted from item IDs, and every token maps to one S2 bbox. Tokens such as <code>0001</code> and <code>1</code> refer to different bboxes, so parsing the token as an integer or stripping leading zeros would merge distinct locations and cause leakage. The upstream documentation describes 337 locations; the discrepancy remains open. The local split uses only observed IDs and does not merge or invent groups.
- **No official split assignment was found.** A scan of the local JSON documents found no <code>split</code>, <code>subset</code>, or <code>partition</code> field. A deterministic local split grouped by the exact sequence token is now generated by the M8 preparation script.
- **Sentinel-2 bands are separate files at mixed resolutions.** A sampled scene has uint16 GeoTIFFs: B02/B03/B04/B08 at 10 m (512×512), B05/B06/B07/B8A/B11/B12 at 20 m (256×256), and B01/B09 at 60 m (85×85). The available Level-2A band set is B01, B02, B03, B04, B05, B06, B07, B08, B09, B11, B12, and B8A; B10 is absent. The sampled scene is EPSG:32628, but scene CRS can vary by location.
- **The first common-grid contract is implemented.** Each scene uses its B05 raster as the 20 m target grid. Finer 10 m bands use area averaging, coarser 60 m bands use bilinear interpolation, and same-resolution bands use nearest-neighbor resampling. Rasterio nodata masks are propagated; the returned common validity mask is true only where every selected band has support. This choice standardizes the tensor shape but does not add spatial detail to 60 m bands.

## M8 implementation result

The adapter and sequence-group split are implemented in `src/georag/data/sen12flood.py` and `src/georag/data/splits.py`. Run the local catalog/split preparation from the repository root:

```powershell
uv run python scripts/prepare_sen12flood.py --config configs/milestone_8.toml
```

The verified local catalog has 2,236 rows, 2,138 scenes with all twelve optical rasters present, 98 metadata-only rows, and 335 exact sequence groups. Scene tensors are float32 `[12, 256, 256]` raw DN values by default (`value_scale = 1.0`); this adapter does not claim calibrated reflectance. Four complete scenes sampled across the catalog loaded successfully. This is a smoke check, not a full raster-corruption audit.

The generated manifest is `data/splits/sen12flood_s2_seed_17.csv` (ignored by Git), with SHA-256 `d1ef22ad1dc00e65099c98eec9ee8134b3d75405fc5a743a1bcf9549ce11785f`. Split counts include metadata-only rows:

| Split | Records | Available | Missing | Flood | No flood | Sequence groups |
|---|---:|---:|---:|---:|---:|---:|
| Train | 1,789 | 1,708 | 81 | 396 | 1,393 | 232 |
| Validation | 224 | 210 | 14 | 58 | 166 | 52 |
| Test | 223 | 220 | 3 | 75 | 148 | 51 |

The adapter retains all catalog rows through `all_records`; ordinary dataset iteration and `records` expose only scenes with all selected TIFF files. The sequence-group split acts on the full catalog, so missing files do not cause a location to be reassigned. When applying these full-catalog assignments to `dataset.records`, use `indices_for_split(..., allow_extra_assignments=True)`; strict exact-ID checking remains the default for manifest validation.

The adapter fills invalid tensor cells with zero for finite model input and returns a separate `valid_mask`. A future training pipeline must use that mask when computing normalization statistics and decide how spatial augmentations transform it; treating fill zeros as valid ground observations would introduce a no-data artifact.

Verification: the complete repository test suite passes (80 tests after the M8 additions; warnings are Rasterio's `from_origin` pending-deprecation warning). Synthetic data tests cover collection pairing, label parsing, path safety, band order/shape, missing files, nodata-mask collation, split determinism, group isolation, and applying full-catalog splits to available scenes. The local data smoke test loaded four scenes; no model training or flood-retrieval evaluation has been performed.

## Evaluation and implementation consequences

1. Build records from STAC item JSON, pairing source and label IDs by exact sequence/date suffix. Parse boolean-like label strings explicitly and retain original values for provenance.
2. Extract the exact textual sequence token from item IDs and use it as the group key. Do not use the numeric value as the key.
3. Validate every asset path referenced by STAC. Distinguish absent raster files from valid scene labels and from FULL-DATA-COVERAGE.
4. Use Sentinel-2 for the first RGB-versus-multispectral experiment. Sentinel-1 is a later experiment because its acquisition dates and item counts differ.
5. Before training, keep the generated sequence-group split fixed; separately define model normalization and the query/relevance protocol. The usable-scene and 20 m resampling policies are now explicit in `configs/milestone_8.toml`.

No model was trained and no retrieval-quality claim follows from this audit.
